# Атомные привычки - Backend API Трекера Привычек 🏃‍♂️ Habit Tracker

Бэкенд-часть SPA веб-приложения для трекера полезных привычек, разработанная на основе бестселлера Джеймса Клира
«Атомные привычки». Проект реализует логику формирования привычек, их валидацию, защиту персональных данных,
постраничный вывод и автоматические напоминания пользователям в мессенджер Telegram по расписанию.

## 🛠 Технологический стек

* **Язык разработки:** Python 3.12
* **Фреймворк:** Django 5.0+ & Django REST Framework (DRF)
* **Аутентификация:** JWT (django-rest-framework-simplejwt)
* **Асинхронные задачи и планировщик:** Celery & Celery Beat
* **Брокер сообщений / Кэш:** Redis
* **Прокси-сервер:** Nginx (раздача статики и медиа в контейнере)
* **Безопасность:** Django CORS Headers, Django Environ
* **Документация:** drf-yasg (Swagger / ReDoc)
* **Контейнеризация:** Docker & Docker Compose
* **Автоматизация:** GitHub Actions (CI/CD)

## 🏗 Ключевая бизнес-логика и валидаторы

В соответствии с методологией книги, модель привычки содержит жесткие правила, которые проверяются на уровне
сериализаторов:

1. **Исключение дублирования вознаграждения:** Нельзя одновременно выбрать связанную приятную привычку и текстовое
   вознаграждение. Можно заполнить только одно из двух полей.
2. **Ограничение по времени:** Время на выполнение привычки должно быть не больше **120 секунд (2 минут)**.
3. **Фильтр связей:** В качестве связанных привычек могут выступать только те объекты, у которых установлен флаг
   приятной привычки (`is_pleasant=True`).
4. **Ограничения для приятных привычек:** Сама приятная привычка не может иметь своего вознаграждения или своей
   связанной привычки.
5. **Регулярность:** Привычку нельзя выполнять реже, чем 1 раз в 7 дней (периодичность от 1 до 7 дней).

## 🚀 Пошаговое руководство по локальному запуску через Docker

Благодаря контейнеризации, теперь весь проект со всеми зависимостями и базами данных поднимается **одной командой**.

### 1. Клонирование репозитория
```bash
git clone https://github.com/lenaLeshukova/habit_tracker.git
cd habit_tracker
```

### 2. Настройка переменных окружения
Создайте локальный файл **`.env`** в корневом каталоге проекта на основе шаблона `.env.template`:
```env
SECRET_KEY='django-insecure-ваша_секретная_строка'
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1,web

# Настройки базы данных PostgreSQL (внутри Docker)
DB_NAME=habit_db
DB_USER=postgres
DB_PASSWORD=ваш_пароль_бд
DB_HOST=db
DB_PORT=5432

# Telegram Settings
TELEGRAM_BOT_TOKEN=токен_вашего_телеграм_бота

# Celery & Redis (внутри Docker)
CELERY_BROKER_URL=redis://redis:6379/0
CELERY_RESULT_BACKEND=redis://redis:6379/1

# CORS Settings
CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

### 3. Запуск проекта одной командой
В терминале PyCharm выполните команду:
```bash
docker compose up --build --force-recreate
```
*Docker автоматически соберет образы, накатит миграции базы данных PostgreSQL, соберет статические файлы и запустит веб-сервер, Celery-воркер, Celery-планировщик и Nginx. Приложение станет доступно по адресу `http://localhost`.*

---


### 3. Миграции и создание суперпользователя

```bash
# Подготовьте и примените миграции базы данных
python manage.py makemigrations
python manage.py migrate

# Создайте администратора (в качестве логина используется Email)
python manage.py createsuperuser
```

### 4. Запуск сервисов

Для полноценной работы приложения вам потребуется запустить три параллельных процесса в разных терминалах PyCharm:

```bash
# Терминал 1: Запуск Django веб-сервера API
python manage.py runserver

# Терминал 2: Запуск Celery Worker (выполнение задач)
celery -A config worker --loglevel=info -P solo

# Терминал 3: Запуск Celery Beat (планировщик ежеминутных напоминаний)
celery -A config beat --loglevel=info
```

## 🔄 Настройка CI/CD и автоматического деплоя (Yandex Cloud)

В проект внедрена система непрерывной интеграции и деплоя **GitHub Actions** (сценарий находится в `.github/workflows/deploy.yml`).

 При каждом открытии **Pull Request** в ветку `develop` пайплайн автоматически:
1. Проверяет код линтером `flake8`.
2. Прогоняет авто-тесты Django.
3. Верифицирует возможность сборки Docker-образов.

 При выполнении **Push** (слиянии) в ветку `develop` или `main` пайплайн автоматически подключается к удаленному серверу Ubuntu в **Yandex Cloud** по SSH и обновляет приложение без прерывания его работы.

### Настройка секретов для деплоя:
Для работы авто-деплоя перейдите в вашем GitHub репозитории в *Settings -> Secrets and variables -> Actions* и добавьте следующие секреты:
* `SSH_HOST` - Публичный IP-адрес вашей ВМ Yandex Cloud (`81.26.187.178`).
* `SSH_USER` - Имя пользователя вашей ВМ (`admin1`).
* `SSH_PRIVATE_KEY` - Ваш приватный SSH-ключ (содержимое файла `id_ed25519`).
* `SSH_PASSPHRASE` - Кодовая фраза (Passphrase) от вашего SSH-ключевого файла.
* `ENV_FILE` - Полное содержимое продакшн-файла `.env`.
